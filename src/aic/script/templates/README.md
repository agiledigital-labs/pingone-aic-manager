# AIC scripts workspace

This directory is a local workspace for PingOne Advanced Identity Cloud (AIC)
scripts, synced by [`aic-edit`](https://github.com/agiledigital-labs/aic-edit).
It holds the editable source of one **tenant**'s AM scripts and IDM endpoints,
with TypeScript definitions so your editor gives full IntelliSense on the
script bindings. AM scripts are **realm-scoped** (`am/<realm>/…`); IDM endpoints
are tenant-global (`idm/endpoint/…`).

You edit the `.cjs` files here; `aic script pull`/`push` keep them in sync with
the tenant. Conflict detection is **content-based** (AIC scripts have no
revision id): a push only overwrites the remote when it still matches what you
last pulled.

## Project structure

```
am/
  types/                         # managed: layered TypeScript binding defs
    rhino-1.7.14.d.ts            #   Java/Rhino interop types (shared)
    common.d.ts                  #   next-gen common bindings (logger, httpClient, openidm, utils, …)
    decision-node-base.d.ts      #   bindings shared by both decision engines
    decision-node-next.d.ts      #   next-gen-only decision bindings
    decision-node-legacy.d.ts    #   legacy-only decision bindings
    library.d.ts  oidc-claims.d.ts
  tsconfig.json  eslint.config.js
  alpha/                         # one subtree per realm (alpha, bravo)
    decision-node/        <Name>.cjs   # scripted decision node (next-gen)
    decision-node-legacy/ <Name>.cjs   # scripted decision node (legacy engine)
    lib/                  <Name>.cjs   # LIBRARY (+ <Name>.js ES-module wrapper)
    oidc-claims/          <Name>.cjs   # OIDC_CLAIMS
    oauth2-access-token/ saml-idp-adapter/ …   # one folder per script type
  bravo/  (same shape as alpha)
  # Each AM script type gets its own folder (short slug of its `context`) with a
  # leaf tsconfig.json that includes just the right types/ defs; `…-ng` = next-gen
  # variant. Groovy scripts are not synced.
idm/
  types/                 # managed: rhino-1.7.14, common, endpoint, schedule defs
  tsconfig.json  eslint.config.js
  endpoint/ tsconfig.json  <name>.cjs  # IDM custom endpoints (/openidm/config/endpoint/*)
  schedule/ tsconfig.json  <name>.cjs  # IDM scheduled jobs (/openidm/config/schedule/*)
tools/check-types.mjs  # managed: per-folder type-check runner (npm run type-check)
tests/                 # your Jest tests
package.json  .prettierrc
.aic-sync/             # tool-managed: last-synced snapshots (per realm + idm)
                       # + templates version (gitignored; never edit by hand)
```

Files marked *managed* (everything under `types/`, the `tsconfig.json`,
`eslint.config.js`, and `tools/`) are regenerated by `aic script workspace
update`; everything else is yours. Update also deletes managed files retired in
newer template versions, so don't add your own files under `types/`.

### Rhino quirks the lint rules enforce

AM scripts run on **Mozilla Rhino 1.7.14**, which only partially supports ES2015.
The ESLint config flags the constructs that are runtime-verified to break
(see `docs/api/12-script-bindings-matrix.md` in the aic-edit repo and
`scripts/rhino-script-tester/`):

- `let` anywhere — **parse error** (`missing ; before statement`). Use `var`,
  or `const` *inside a function*.
- object shorthand `{ a }`, object/array destructuring, default parameters —
  **parse errors**.
- `const` in a `for`/`for-in`/`for-of` initializer — **parse error**; `const` at
  the top level or in a loop body parses but reads back `undefined`.
- Arrow functions, template literals, and ES2015 `Array`/`String`/`Object`
  methods all work and are allowed.

IDM scripts also run on Rhino, but their exact behaviour is not yet
runtime-verified, so IDM lint intentionally does not yet enforce these bans.

## Syncing with the tenant

Scripts are addressed by a **full-name** `<namespace>/<name>`, where the
namespace is `alpha`/`bravo` (AM realm), `endpoint`, or `schedule`. `aic` walks
up to the project root and infers the tenant from the `workspace/<tenant>/…`
path, so no `--tenant` is needed here. A **bare name** (no prefix) uses the
namespace of the directory you're in.

```bash
aic script list                      # all scripts; each row tagged with its full-name `ref`
aic script list bravo                # just one namespace
aic script pull                      # no ref: fuzzy-pick one (`!` local changes, `-` not pulled)
aic script pull bravo/MyNode         # pull one AM script (bravo realm)
aic script pull endpoint/myEndpoint  # pull one IDM endpoint
aic script pull schedule             # pull a whole namespace
aic script pull all                  # pull everything (both realms + endpoints + schedules)
aic script push                      # no ref: fuzzy-pick one (locally-changed marked `!`)
aic script push bravo/MyNode         # push your edit back (content-checked)
aic script push all                  # push every locally-changed script
aic script sync                      # reconcile: push local-only, pull remote-only, resolve conflicts
aic script sync --resolve remote     # force any conflict to the tenant's copy
aic script watch                     # auto-push each script you save (Ctrl-C to stop)
aic script status                    # in sync / modified locally / remote / conflict
aic script diff                      # no ref: fuzzy-pick a synced script
aic script diff schedule/MyJob       # local-vs-tenant diff (via git; pipe to delta etc.)
aic script diff schedule/MyJob --local-vs-snapshot   # just your edits since last pull
aic script diff schedule/MyJob --snapshot-vs-remote  # tenant drift since you pulled
aic script workspace update          # refresh the managed types/config
```

Notes:
- Namespaces: `alpha`/`bravo` (AM scripts, by realm), `endpoint` (IDM custom
  endpoints), `schedule` (IDM scheduled jobs — only script-invoking ones).
- A pull that would overwrite un-pushed local edits backs them up under
  `.aic-sync/backups/` first (use `--force` to skip the backup).
- A push is blocked only if the remote changed since your last sync (resolve
  from the `diff`, or re-run with `--force`). Product-default scripts are
  editable like any other — they push without `--force`.

## Local development

These run in this directory and use the bundled TypeScript / ESLint / Jest
config:

```bash
npm install
npm run type-check   # tsc --noEmit per script folder (tools/check-types.mjs)
npm run lint         # ESLint per product (lint:fix to autofix)
npm test             # Jest
```

`type-check` runs `tsc` once per script folder rather than as one big program:
each family's `.d.ts` set is scoped to its folder's leaf `tsconfig.json`, because
some bindings (e.g. the legacy-OIDC vs next-gen `logger`) deliberately differ.

The TypeScript definitions cover the ForgeRock/AIC script globals (`logger`,
`openidm`, `nodeState`, callbacks, OIDC claims context, IDM `request`/`context`,
etc.) per script type.

# TypeScript custom endpoints

Implemented in: `src/scripts/templates/typescript/` (the embedded project),
`src/scripts/ts_project.rs` (the ownership manifest), `src/scripts/workspace.rs`
(scaffolding), `src/scripts/managed_types.rs` (module-form tenant types),
`src/scripts/cli.rs` (`workspace update`, `script watch`).

API ground truth: `docs/api/11-idm-endpoints.md`,
`docs/api/12-script-bindings-matrix.md`.

## The problem

An IDM custom endpoint is one JavaScript string in a config object, and IDM has
**no module system you can extend**: `require()` resolves exactly three bundled
libraries (`lib/lodash` 3.10.1, `lib/handlebars` 4.7.7, `lib/validator` 13.7.0)
and there is no SaaS-exposed path to add a fourth. Two endpoints that need the
same validation rule, the same log format, or the same business logic can only
inline it in both, or pay an `openidm.action` hop to a third endpoint
(`docs/sharing-code-between-am-and-idm.md`).

Nothing about that changes at runtime. So this feature shares code at **build
time** instead: endpoints are ordinary TypeScript modules, and the build bundles
each one into a single self-contained ES5 file at
`workspace/<tenant>/idm/endpoint/<name>.cjs`. From there it is an ordinary IDM
endpoint that the existing sync engine pushes.

## Layout

```text
workspace/<tenant>/typescript/
  framework/          MANAGED  routing, validation, logging, errors, OpenAPI
  tools/              MANAGED  build pipeline + generated-bundle linter
  tests/              MANAGED  framework tests (plus your own)
  package.json        MERGED   framework toolchain refreshed, your deps kept
  src/endpoints/      USER     one file per endpoint; file name = endpoint name
  src/shared/         USER     shared modules
  src/generated/      GENERATED by `aic workspace update` (gitignored)
  openapi/            GENERATED one OpenAPI 3.1 document per endpoint
  .aic-ts-manifest.json  GENERATED the endpoints this project owns
```

`package.json` is deliberately neither managed nor seeded-once. Overwriting it
would drop a dependency the user's endpoints need; seeding it once would strand
the two-step build on whatever esbuild and Babel were current when the workspace
was created, which is precisely the class of breakage `TEMPLATES_VERSION` exists
to prevent. `workspace::merge_package_json` refreshes the framework's own keys
and leaves everything else alone.

## The build

`esbuild` cannot target ES5 at all — it refuses with
`Transforming const to the configured target environment ("es5") is not supported yet`
— and Babel cannot bundle. So the pipeline is two tools:

1. `tsc --noEmit` over the endpoint program and then the test program.
2. esbuild bundles each endpoint to one ES2020 IIFE
   (`--format=iife --global-name=__aicMain --platform=neutral`).
3. Babel `@babel/preset-env` with `targets: { ie: "11" }` downlevels it to ES5.
   Babel 8 removed `loose`; the equivalent output shape comes from `assumptions`
   (`constantSuper`, `noClassCalls`, `setClassMethods`,
   `superIsCallableConstructor`, `noDocumentAll`).
4. The **generated** file is linted against IDM's runtime bans (below).
5. Only if every endpoint clears every step is anything written to disk, so a
   broken build cannot leave a half-updated `.cjs` for `aic script watch` to
   push.

The emitted file ends with the expression statement `__aicMain.default();`
because an endpoint's HTTP response body is the script's completion value.
Bundle size is not a constraint: 2 MB of parsed source deploys and executes
(probed 2026-08-13); the demo endpoints are ~40–45 KB.

## Never subclass `Error`

`Reflect` is `undefined` on the IDM script engine. Babel's `_wrapNativeSuper`
helper falls back off `Reflect.construct` and does not restore the subclass
prototype, so for `class Fault extends Error`:

```javascript
new Fault("x") instanceof Error; // true
new Fault("x") instanceof Fault; // FALSE
```

`.name` and `.message` survive; the identity does not. Any `instanceof`-based
error discrimination therefore classifies every fault as "unknown" and
returns 500. Plain class-to-class inheritance is unaffected — only native
`Error`.

The framework uses a tagged plain object (`framework/errors.ts`) and duck-types
it, and `typescript/eslint.config.js` rejects both `extends Error` and an
`instanceof …Error` test.

## Runtime bans, checked on the generated file

Three constructs make an endpoint fail to **register** — an un-routable 404, not
a misbehaviour — so they are build failures, not warnings:

| Ban                                       | Why                                          |
| ----------------------------------------- | -------------------------------------------- |
| default parameter values                  | the IDM engine fails to compile the function |
| `const` in a `for`/`for-in`/`for-of` init | same                                         |
| trailing comma in a **parameter** list    | same (a trailing comma in a _call_ is fine)  |

The hand-written `.cjs` endpoints get these from `idm/eslint.config.js`. A
bundle cannot go through that config — it would also have to satisfy
`prettier/prettier`, which is meaningless for generated output — so
`tools/idm-runtime-bans.mjs` re-implements the same three checks over the
emitted file with `@babel/parser` (the trailing-comma one from the token stream,
since the AST does not record it).

## Keeping generated files out of the hand-written gates

Three exclusions, all driven by facts rather than by a hand-maintained list:

- **`tsc`** — the banner carries `// @ts-nocheck`, so
  `idm/endpoint/tsconfig.json` still includes the file but reports nothing in
  it. This beats a static `exclude` glob, which would have to guess the names,
  and it works in the editor as well as in CI.
- **ESLint** — `idm/eslint.config.js` reads `.aic-ts-manifest.json` at config
  load time, `ignores` exactly those files in the hand-written block, and adds a
  second block for exactly those files carrying the runtime bans and nothing
  else.
- **Prettier** — the build rewrites a marked block at the end of
  `workspace/<tenant>/.prettierignore`; anything above the marker is the user's.

## The ownership manifest, and why `watch` needed one

`aic script watch` skipped any file whose `local_state` was `Missing`
(untracked), silently. That made a generated endpoint impossible to deploy: it
has no sync snapshot until it exists remotely, and nothing would push it because
it had no snapshot.

`.aic-ts-manifest.json` breaks the cycle by declaring which endpoints the
project owns, so watch can tell "intentionally generated" from "stray file". A
declared-but-untracked endpoint is **created** on the tenant (through
`sync::create`, which carries the same prod guard as a push and pulls the
server's copy back), after which every later save takes the ordinary tracked
path. Hand-written `.cjs` files are unaffected: an untracked one is still
skipped.

## Tenant-derived types

`aic workspace update` already writes ambient `idm/types/managed/*.d.ts` for the
`.cjs` workspace. Ambient declarations are invisible inside a module graph, so
`managed_types::generate` additionally emits
`typescript/src/generated/managed.ts` — the same schema as `export`ed
declarations plus an exported `ManagedObjects` collection map.

## OpenAPI and the `?_action=` problem

CREST puts `create` and every named action on `POST <path>?_action=<name>`, and
`read` and `query` both on `GET <path>`, so several operations collide on one
(path, HTTP method) key — which OpenAPI cannot express.

The generator keeps **one operation per declared route** and disambiguates with
a `:<name>` path-key suffix (`/{widgetId}:retire`), the Google AIP-136 RPC
convention. An action route always gets the suffix, whether or not it currently
collides, so adding a second action later cannot silently move the first one's
key. A `read`/`query` collision moves the `query`. Every operation carries the
machine-readable truth — `x-crest-method`, `x-crest-action`, `x-crest-path`,
`x-crest-synthetic-path-key` — plus a \*\*required `_action` (or `_queryFilter`)
query parameter pinned by a single-value `enum`, so a client that ignores the
extensions still sends the right query string.

The alternative — one POST per path with a `oneOf` body and a free `_action`
enum — types nothing per action and loses the per-action scope requirement,
which is the opposite of the point of the project.
